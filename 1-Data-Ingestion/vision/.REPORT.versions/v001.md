# Pitcher Delivery Time from Broadcast Video — Vision Pipeline Report (v1)

**BLUF:** A BaseballCV + RTMPose pipeline measures pitcher delivery time (lead-foot lift-off → ball release)
from Baseball Savant broadcast clips, behind a camera-QA gate that runs first. On the 50 clips hand-labelled
in the May 2026 pilot it passes all three of that pilot's go/no-go gates, where the May pilot failed two:
**release error 1.83 frames, same-pitcher spread ≤ 0.060 s, 76% of clips usable**. It is ready for a
random 500-clip pilot, then the full run over the ~11,140 SB/CS attempts.

**XYZ:** Achieved a validated, reproducible delivery-time measurement, as measured by release MAE 1.83
frames (95% CI 1.57–2.10), lift-off MAE 1.70 frames (leave-one-out 1.7), within-pitcher ICC(1) = 0.94 and
76% QA coverage against the hand labels (May pilot: 132.75 frames, SD 0.378 s), by building
`cv/delivery_time.py`. The camera-QA gate comes first; BaseballCV detectors handle shot classification,
ball flight and field scale; RTMPose foot keypoints run inside the detected pitcher box; Statcast plate
time checks the release physically.

---

## 1. Problem and definitions

| Term | Operational definition (what the code measures) |
|---|---|
| **Lift-off (start)** | First frame the glove-side foot's lowest keypoint (heel / toes) rises ≥ 0.75 in above a still set position, relative to the planted pivot foot |
| **Release (end)** | First frame BaseballCV's ball detector places the ball on its flight trajectory (back-extrapolated from the flight) |
| **Delivery time** | (release − lift-off) / clip fps, in seconds |
| **Camera QA PASS** | One uncut centre-field shot over the delivery, steady camera, release at the hand, ball tracked to the plate |
| **Gold set** | 50 Savant clips hand-labelled frame by frame by the user in May 2026 (`cv/gold/labels_manual.csv`) |

Population: SB and CS attempts in `Data/Raw_Attempts.csv` (11,140 of 12,021). Pickoffs (453) and balks
(349) are excluded because no pitch reaches the plate; 79 rows coded FB are also excluded.

## 2. Architecture

```
play_id ─► Savant clip (HOME feed; AWAY on QA failure)        fetch()       sporty-videos?playId=…[&videoType=AWAY]
        ─► shot cuts (PySceneDetect AdaptiveDetector)          cuts()
        ─► CF-picture test per shot (BaseballCV phc_detector    scene(), is_cf()
             + glove_tracking: pitcher / catcher / homeplate / rubber)
        ─► ball flight in a 640 px corridor slice (SAHI-style)  flight()      BaseballCV ball_tracking_v4
             chained by constant-velocity prediction, extended back to the release
        ─► camera-QA gate (§4)                                  decide()
        ─► RTMPose-m Halpe-26 feet inside the BaseballCV pitcher box → lift-off   lift_off()
        ─► delivery_s
```

Detected objects come from BaseballCV (github.com/dylandru/BaseballCV), using weights only (see §8):

| Model | Arch / input | Classes used | Role |
|---|---|---|---|
| `pitcher_hitter_catcher_detector_v3` | YOLOv8l, 800 | pitcher, catcher, hitter | CF test, pose crop, speed scale |
| `glove_tracking_v4` | YOLO11, 800 | homeplate, rubber | CF test, scale (rubber = 24 in) |
| `ball_tracking_v4` | YOLO11x, 640 | baseball | release + flight |
| RTMPose-m Halpe-26 (rtmlib) | 256×192, ONNX CPU | ankle / heel / toe keypoints | lift-off |

Design rule: expensive detections are cached per clip and feed (`cv/cache/det/*.json`), and every decision
is a pure function of that cache plus `CFG`. Scoring 1, 5 or 11,000 clips therefore yields identical rows
for a given clip (§5.6).

## 3. Results on the gold set (n = 50 clips)

Source: `cv/.venv/bin/python cv/delivery_time.py gold` → `cv/out/eval_gold.csv`. Frame-level errors are
computed only where the analysed clip is the exact mp4 that was labelled (HOME feed, same CDN token,
n = 30). Error = auto − hand label. LoA = Bland–Altman 95% limits of agreement. CIs are 2,000-sample
bootstraps.

### 3.1 Go/no-go gates (the May pilot's own)

| Gate | Threshold | **v1** | May pilot | Verdict |
|---|---|---|---|---|
| Release error (MAE) | ≤ 2 frames | **1.83 frames** (CI 1.57–2.10) | 132.75 | PASS |
| Within-pitcher delivery SD | ≤ 0.10 s | **max 0.060 s**, median 0.023 (7 pitchers ≥ 2 clips) | 0.378 | PASS |
| Coverage (QA PASS) | ≥ 70% | **76%** (38/50; 30 HOME, 8 AWAY) | 75% (with wrong releases) | PASS |

### 3.2 Agreement with the hand labels

| Quantity | MAE | Bias | LoA | Within tolerance |
|---|---|---|---|---|
| Release (frames) | 1.83 | −1.83 | [−3.30, −0.37] | 87% ≤ 2 frames |
| Lift-off (frames) | 1.70 (CI 1.23–2.23) | −0.03 | [−4.42, +4.35] | 77% ≤ 2, 90% ≤ 3 frames |
| Delivery time (s) | 0.041 (CI 0.033–0.049) | −0.030 | [−0.101, +0.041] | — |

Reading the numbers:
- **The release offset is a convention, not noise.** Its LoA is only about ±1.5 frames wide around −1.83.
  The pipeline marks the first frame the ball is on its flight line; the hand labels mark the frame it is
  clearly separated, about 2 frames (31 ms) later. Visually checked on 6 clips. The −0.030 s delivery bias
  is this offset.
- **Lift-off threshold was chosen by leave-one-out cross-validation** (`delivery_time.py tune`): 0.5 / 0.75
  / 1.0 in gave MAE 1.90 / 1.70 / 1.90 frames, and the held-out MAE is 1.7 frames, so 0.75 in is not
  over-fitted to the labels.

### 3.3 Reliability and physical plausibility (38 PASS clips)

| Metric | Value | Meaning |
|---|---|---|
| ICC(1), delivery by pitcher | **0.94** (21 pitchers, 28 clips) | Delivery time is a stable pitcher trait; the measurement resolves it |
| Delivery time distribution | mean 0.972 s, SD 0.136, range 0.686–1.289 s | Plausible for the stretch (slide step to leg kick) |
| Flight residual: run − (Statcast plateTime + 0.032 s) | mean +0.006 s, SD 0.021 s (≈ 1.3 frames) | Release agrees with an independent physical clock |
| Release-to-wrist distance (× pitcher height) | median 0.15, max 0.47 (gate 0.6) | The ball starts at the throwing hand |
| Field scale source | rubber (24 in) on 38/38, median 4.63 px/in | Inch thresholds are physically scaled |
| Lead foot = glove side (pose L/R) | 25/25 where handedness known | Pose left/right is reliable in the CF view; now enforced |

### 3.4 Camera-QA funnel (the safety step)

| Stage | Dropped | Remaining |
|---|---|---|
| Gold clips | — | 50 |
| no_flight (ball never detected) | −3 | 47 |
| cut_in_window (camera cut during the delivery) | −3 | 44 |
| release_not_at_hand (ball first seen mid-flight) | −2 | 42 |
| flight_too_short (ball not tracked to the plate) | −2 | 40 |
| no_set_before_lift | −1 | 39 |
| not_cf_view | −1 | **38 PASS** |

All 12 rejections were checked visually. Five are correct refusals: three real camera cuts, two of which
the labeller had also flagged "No first move" (e.g. a high-home shot that cuts to centre field 10 frames
before release); the release_not_at_hand pair, e.g. a 70.8 mph curveball lost for 18 frames mid-flight; and
one no-set clip. The rest are detector misses (small balls, occlusion), so they cost coverage, not
accuracy. **Precision of PASS is the priority: no PASS clip had a gross error.** Among the 30 compared
clips, the largest errors are 0.084 s (delivery), 4 frames (release) and 6 frames (lift-off).

## 4. Camera-QA gate (exact rules, `decide()`)

A clip PASSes only if all hold, in this order:

1. **Shot continuity:** no cut in (release − 0.5 s, release + 0.2 s]. An earlier cut is allowed only if a
   still set position (≥ 0.3 s) is visible after it, before lift-off.
2. **CF picture** in every frame sampled at 4 Hz: pitcher in the foreground (≥ 1.2× the catcher's height,
   feet lower in frame), catcher beyond him, home plate beyond the pitcher wherever visible (seen ≥ once).
3. **Steady camera:** pitcher's and catcher's foot positions drift ≤ 10% of pitcher height. This guards
   against pans, zooms and picture-in-picture.
4. **Release at the hand:** first flight point ≤ 0.6 pitcher heights from a wrist one frame earlier.
5. **Ball tracked to the plate:** flight run ≥ Statcast plateTime + 0.032 − 0.04 s.
6. **Lift-off found** after a still set position, and delivery time within 0.45–2.0 s.

## 6. How to fit this to the ~10k base-stealing attempts

The pipeline is not trained on your attempts. Its detectors are pre-trained and its thresholds are fixed
in `CFG`. "Fitting" means **running it over every attempt, then feeding `delivery_s` to the steal model.**

**Step 1 — random pilot (≈ 10 h, overnight).** Measures the real QA pass rate; the gold set was selected,
not random.
```bash
cd ~/Desktop/StealIQ
cv/.venv/bin/python cv/delivery_time.py pilot 500
```
Output: `cv/out/delivery_pilot.csv` plus the funnel table. **Go to step 2 only if PASS ≥ 60%** and a spot
audit of 20 PASS sheets shows no gross error:
```bash
cv/.venv/bin/python -c "import sys; sys.path.insert(0,'cv'); import delivery_time as D; print(D.sheet('<play_id>'))"
```

**Step 2 — full run (≈ 9–10 days on this Mac; resumable).** Restarting skips every cached clip, and video
is deleted after detection.
```bash
caffeinate -i cv/.venv/bin/python cv/delivery_time.py all > cv/cache/all_run.log 2>&1
```
Re-run the same command after any interruption. A CUDA GPU would cut this roughly 5–10×.

**Step 3 — join to the attempts table** (one row per play_id; keep QA status, never impute):
```python
import pandas as pd
A = pd.read_csv("Data/Raw_Attempts.csv")
D = pd.read_csv("cv/out/delivery_all.csv")[["play_id", "qa", "feed", "delivery_s", "lift_frame", "release_frame"]]
A = A.merge(D, on="play_id", how="left")
A.loc[A.qa != "PASS", "delivery_s"] = None        # only QA-passed measurements
A.to_csv("Data/Raw_Attempts_delivery.csv", index=False)
```

**Step 4 — features for `model/engines.py`:**
- `delivery_s`: per attempt (missing where QA failed). XGBoost handles NaN natively; logistic models need
  the per-pitcher value below.
- `pitcher_delivery_s`: per-pitcher median, **computed on training folds only** with shrinkage toward the
  league mean (n/(n+k)). ICC 0.94 means few clips per pitcher suffice.
- Add both as a new group (e.g. `DELIVERY_FEATS`) next to `ARM_FEATS`, then rerun the ablation table in
  `main_v12()`.

**Step 5 — validation before keeping the feature:**
- **Collinearity:** `gain_to_release_ft` (runner ground gained up to release) physically contains delivery
  time. Report VIF / Belsley–Kuh–Welsch condition indices for the feature set, not pairwise correlations.
- **Missingness bias:** compare outcome rates and lead distances for QA-PASS vs QA-fail attempts. If they
  differ, coverage is not random, and the missing indicator itself must be a feature or the analysis
  restricted.
- **Gain:** grouped-by-runner CV AUC and reliability curve, with vs without `DELIVERY_FEATS`, same splits.
  Keep the feature only if AUC improves beyond CV noise.
- **Physical check:** within a runner, `gain_to_release_ft` should rise with `delivery_s`. The slope (ft/s)
  should be a plausible secondary-lead speed. This validates the feature independently of the outcome.

## 7. Limitations

- **Gold is n = 50 and mostly 2024**, from one labeller and not a random sample. Accuracy holds there;
  the random-sample pass rate is unmeasured until step 1.
- **Release convention differs from the labels by −2 frames (31 ms).** It's fine for comparing pitchers.
  For absolute times, decide the convention and shift if needed (one line).
- **Lift-off for slow slide steps is the least certain event.** LoA ±4.4 frames, worst single error 6
  frames.
- **Coverage loss is concentrated in wide camera shots** (small ball) and curveballs (ball lost
  mid-flight).
- **Delivery is only measurable on attempt pitches.** It cannot be added to the attempt-decision model on
  `Raw_Opportunities` unless non-attempt pitches are also processed.

## 8. Decisions and what was ruled out

- **BaseballCV's weights are used, not its package.** Importing it auto-installs a third-party git fork and
  pins old dependencies; the Savant scraping logic is mirrored instead.
- **open-command (tomdoyo)** contributed method (the late-CF-cut funnel, ball timing vs Statcast). Its data
  cannot validate release frames because each clip is re-indexed so release ≈ 0.
- **Ruled out:**
  - pose-based release (the May failure mode)
  - single-frame shot classification
  - requiring the rubber or home plate in every frame
  - home-plate width as a zoom cue
  - speed/turn-based catch detection and net-displacement filters (the pitch's image path is an arc)
  - heel-rise as lift-off (labels mark the whole foot leaving)
  - vertical-only stillness (fails on slide steps)
